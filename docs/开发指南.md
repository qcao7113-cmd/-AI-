# 开发指南

## 一、分层架构

```
pages（业务页面） → components（通用组件） → utils / types
        ↓
      lib/api（数据层） → localStorage
        ↓
   context（全局状态：认证 / 权限 / 提示）
```

- **pages**：只负责页面编排与交互，不直接读 `localStorage`
- **lib/api.ts**：唯一的“后端”边界，所有数据读写都经过它
- **context**：跨页面共享的认证状态与全局提示
- **components**：不含业务语义，可整体迁移到其他项目

## 四、样式约定

- **颜色只允许使用 CSS 变量**（`var(--brand)`、`var(--text-2)` 等），禁止硬编码色值，否则深色模式会失效
- 设计令牌集中在 `src/styles/tokens.css`，改主题只需改这一处
- 新页面样式统一追加到 `src/styles/pages.css`
- 密度变量 `--density` 用于控制紧凑模式下的间距

## 六、接入真实后端

### 1. 替换数据层

`src/lib/api.ts` 中每个函数的签名都已经按真实接口设计，替换函数体即可：

```ts
// 前
export async function listUsers(q: UserQuery): Promise<Paginated<User>> {
  await delay()
  const rows = load().users.filter(/* ... */)
  return paginate(rows, q.page, q.pageSize)
}

// 后
export async function listUsers(q: UserQuery): Promise<Paginated<User>> {
  const params = new URLSearchParams({ page: String(q.page), pageSize: String(q.pageSize) })
  if (q.keyword) params.set('keyword', q.keyword)
  const res = await fetch(`/api/users?${params}`)
  if (!res.ok) throw new ApiError('加载用户失败', res.status)
  return res.json()
}
```

### 2. 登录改为真实 JWT

- `login()` 返回 `Session`，把 `token` 换成后端签发的 JWT
- 在 `src/lib/api.ts` 增加统一的请求封装，从 `localStorage` 读取 `Authorization: Bearer <token>`
- 收到 401 时调用 `logout()` 并跳转登录页

### 3. 权限改为后端下发

- 将 `currentPermissions()` 改为从接口 `/api/me/permissions` 获取
- `context/AppContext.tsx` 中 `AuthProvider` 初始化时请求一次即可

### 4. 移除模拟数据

删除 `src/lib/seed.ts` 与 `createDb()` / `load()` / `persist()` 相关内容即可。

## 七、开发环境注意

- Vite 已开启 `server.watch.usePolling`，避免部分 Windows 编辑器原子写入触发 `EBUSY`
- 路径别名 `@/` 指向 `src/`，`tsconfig.app.json` 与 `vite.config.ts` 需同步维护
- 修改数据模型后，若浏览器中还存着旧数据结构，请在「系统设置 → 重置演示数据」
